## 1. [Hindsight](https://github.com/vectorize-io/hindsight)
- **增量 / 总 Star**：+1607 / 27,684
- **技术栈**：Python / Agent Memory
- **通俗说明**：让 Agent 不只是检索旧对话，而是持续形成事实、经历、观察和心智模型的长期记忆系统。
- **目标用户**：长期运行的客服/销售/研究 Agent、个人助理、企业 Agent 平台。
- **问题/旧方案**：传统 memory 多数只是向量检索聊天历史，能记住但很难从多次经历形成稳定认识。；RAG、向量数据库、知识图谱或把历史对话直接塞回上下文。
- **机制/架构**：retain / recall / reflect；把记忆组织为 world facts、experiences、observations、mental models。；Python 服务 + memory banks + entity/relation/time + sparse/dense retrieval + LLM reflection。
- **爆火原因**：今日 +1,607，总 Star 约27.7k，是今天最强 Agent 新信号。
- **差异化**：目标从 remember 升级为 learn，并公开长期记忆 benchmark。
- **商业化**：企业 Agent Memory Server、客户画像、销售跟进、研究 Agent、跨模型记忆层。
- **中国机会**：国产模型兼容、私有化、数据权限/遗忘策略、企微客服长期记忆。
- **场景**：客服连续性、销售历史、长期研究、个人助理、Coding Agent 项目经验。
- **风险**：错误记忆会长期污染决策；敏感数据需要删除、过期、权限和审计。
- **启发**：Agent 竞争会从上下文长度转向长期学习质量。
- **判断**：★★★★★+。今天最值得研究的新机会。

## 2. [Google AX](https://github.com/google/ax)
- **增量 / 总 Star**：+1376 / 10,247
- **技术栈**：Go / Agent Runtime
- **通俗说明**：Google 的开放 Agentic orchestration runtime，重点解决生产环境中的 Agent 调度与运行。
- **目标用户**：企业 Agent 平台、云原生团队、大规模后台 Agent 开发者。
- **问题/旧方案**：Agent 进入生产后需要生命周期、状态、分布式调度、执行与可观测。；LangGraph/自建队列/Kubernetes jobs/工作流引擎拼接。
- **机制/架构**：统一 runtime 调度、运行和管理 Agent，并与下层执行基础设施组合。；Go runtime + orchestration/control plane + execution substrate integrations。
- **爆火原因**：今日 +1,376，总 Star 已破10k，连续两日高位。
- **差异化**：关注 runtime/orchestration，而不是应用层 Agent SDK。
- **商业化**：企业 Agent Runtime、私有云集成、权限、成本治理和可观测插件。
- **中国机会**：企业内网 Agent 平台、Coding Agent 后台任务和异步 AI 员工。
- **场景**：后台研究 Agent、Coding Agent 批任务、企业 AI 平台。
- **风险**：项目早期、接口变化快；底层基础设施重。
- **启发**：Agent 技术栈正像云原生一样分层，runtime 会成为独立层。
- **判断**：★★★★★。小团队应做其上层集成和行业方案。

## 6. [Agent Substrate](https://github.com/agent-substrate/substrate)
- **增量 / 总 Star**：+439 / 3,705
- **技术栈**：Go / Kubernetes / gVisor / microVM
- **通俗说明**：为大量长期存在但多数时间空闲的 Agent 提供高密度、安全的执行 runtime。
- **目标用户**：Agent 云平台、Coding Agent、MCP 托管、企业私有 Runner。
- **问题/旧方案**：每个 Agent 独占 VM/容器成本高，休眠 Agent 仍占资源。；Kubernetes Pod、VM、容器池。
- **机制/架构**：actor-worker 多路复用，支持 suspend/resume、snapshot、状态迁移和隔离。；Go + Kubernetes + gVisor/microVM + control plane。
- **爆火原因**：今日 +439，总 Star 3.7k；昨日爆发后仍高增长。
- **差异化**：高密度 stateful Agent execution，而不是构建 Agent。
- **商业化**：私有 Agent Runner、Coding Agent 沙箱、MCP server 托管。
- **中国机会**：企业内网 Agent、代码执行、浏览器/桌面自动化隔离层。
- **场景**：Codex/Claude Code 沙箱、MCP 托管、RL 环境。
- **风险**：项目很年轻；Kubernetes 运维复杂，生产成熟度不足。
- **启发**：Agent 规模化成本会来自执行环境和状态，而不只是 token。
- **判断**：★★★★★。继续重点跟踪。
