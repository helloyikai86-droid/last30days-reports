## 十个项目完整分析

### 1. [VectorCraft](https://github.com/storytold/vectorcraft)

**统计口径**：+1,470（GitDiscover 10/10 快照）；当前总 Star **6,150**。
**技术栈**：Rust / WebAssembly / SVG / MCP / Bézier 工具。
**分类**：AIGC、增长/内容、开发工具、新项目、重点。

**通俗说明**：ArtCraft 团队推出的开源矢量图形编辑器，目标是以纯 Rust 提供接近 Illustrator 的路径、图层、混合、遮罩、文本及矢量创作工作流，同时让 Agent 通过 MCP 操作设计元素。

**目标用户**：品牌设计师、营销素材团队、图标与插画创作者、SVG 自动化产品和有白标编辑器需求的 SaaS 团队。

**核心问题**：图像模型擅长生成成品，却很难保证 Logo、图标、字体路径、包装图和跨尺寸物料的精确可编辑性；专业设计文件的自动批量修改仍依赖人工。

**过去做法**：Illustrator / Affinity Designer / Inkscape 人工编辑；或由 AI 生成 SVG 后手工修路径和版式；更简单的团队直接用图片再生成替代精确编辑。

**工作机制**：设计师或 Agent 操作 Pen、Bezier 锚点、混合、布尔运算、图层与蒙版；命令/工具协议将“移动锚点”“替换文字”“导出多尺寸矢量图”转成可重复指令。

**技术架构**：纯 Rust 图形核心、多平台原生前端、WASM Web 端、矢量场景图、路径/Bezier 工具和 MCP Agent 控制接口。

**近期爆火/加速原因**：10月10日 GitDiscover 记录 +1,470/24h 级别热度；同一团队 PhotoCraft 爆发后，市场继续关注它的矢量编辑和 Agent 可编程专业设计路线。

**核心差异化**：与“AI 画一张图”不同，它把可编辑的路径和图层作为产品核心；人能继续手工改，Agent 能对真实设计对象执行确定性操作。

**商业化/延伸方向**：品牌素材批量生产、矢量图标生成与统一规范、广告多尺寸模板、Agent 可调用的 SVG 编辑 API、企业设计系统白标组件；可售卖托管渲染/模板和行业解决方案。

**中国市场机会**：电商商品主图、手游活动页、公众号插画、企业品牌物料高度依赖多尺寸一致性；可与国内生图模型组合为“生成初稿→矢量化→人工/Agent 精修→批量输出”。

**可借鉴场景**：把同一个品牌 Logo、字标和装饰图改成 16:9、9:16、1:1 等尺寸；批量替换活动名称和权益，仍保留 SVG 图层可编辑。

**风险**：项目处于 active development；复杂 SVG/字体、色彩一致性、导入导出兼容需要压力测试；虽自称 clean-room，商业仍要核验依赖与商标边界。

**启发**：垂直 AIGC 工厂需要“两种引擎”：模型做开放式创意，确定性编辑器保证品牌和版本一致。

**明确判断**：★★★★★。素材自动化价值明确；先验证 SVG 导入、文字精修和批量渲染，而不是判断它是否取代 Illustrator。

### 2. [Microsoft MXC](https://github.com/microsoft/mxc)

**统计口径**：+669（GitDiscover 10/10 快照，老项目加速）；当前总 Star **2,569**。
**技术栈**：Rust / Node SDK / .NET SDK / Bubblewrap / Seatbelt / Windows Sandbox。
**分类**：AI/Agent、企业AI、基础设施、开发工具、重点。

**通俗说明**：Microsoft eXecution Container，为 AI 生成代码、插件和不可信工具提供跨 Windows、Linux、macOS 的沙箱执行与策略控制，通过统一 SDK 调用不同隔离后端。

**目标用户**：企业 AI Agent 平台、Coding Agent、自动化测试、开发工具供应商，以及需要让客户上传代码/脚本的平台。

**核心问题**：让 Agent 真正执行代码时，一旦误读权限或被恶意输入诱导，可能删除文件、访问凭据、对外发送数据；Prompt 约束无法构成操作系统安全边界。

**过去做法**：分别使用 Docker、虚拟机、Windows Sandbox、Bubblewrap 或自写子进程权限限制，跨平台 API 和审计差异很大。

**工作机制**：调用方提交命令、文件系统/网络/UI 权限及容器后端；MXC 验证策略，在 OS-native Sandbox、LXC、MicroVM 等后端执行，然后返回可观察的状态/结果。

**技术架构**：Rust 核心 + 版本化 JSON Policy + Rust/.NET/Node SDK；Windows ProcessContainer/Windows Sandbox，Linux Bubblewrap/LXC，macOS Seatbelt，部分 VM 后端实验性。

**近期爆火/加速原因**：10月9日先前日报仅 +106；GitDiscover 10月10日记录 +669，出现大约6.3倍跳升，属于已有项目的突然加速。官方正在完善 SDK 与多种运行后端。

**核心差异化**：不是另一套 Prompt 安全规则，而是用文件、网络、UI 等系统级能力约束 Agent 进程；企业可以围绕统一策略而不是每个 OS 分别适配。

**商业化/延伸方向**：安全 Agent Runtime、受控 Browser/RPA 执行平台、企业插件沙箱、代码运行 API、执行审计和企业隔离策略管理服务；可按任务数和并发收费。

**中国市场机会**：国内企业客服、OA、游戏运营、支付后台自动化最缺少的是可审计、可撤销的执行环境；可以把 MXC 或其架构作为 Windows Agent Worker 的隔离底座。

**可借鉴场景**：在测试环境执行 Agent 自动生成的脚本；限定仅能访问临时目录和白名单服务；高风险写操作必须审批。

**风险**：不同后端隔离强度不等价，一些后端仍实验性；网络代理/凭据注入设计不当会破坏沙箱边界；必须实际红队测试。

**启发**：企业 AI 员工从“能操作”到“敢授权”之间，隔离、审批、审计可能比模型本身更容易形成商业壁垒。

**明确判断**：★★★★★+。增速再次加快，最值得做成“企业 Agent 执行安全层”的基础设施案例。

### 3. [CADCraft](https://github.com/storytold/cadcraft)

**统计口径**：+596（GitDiscover 10/10 快照）；当前总 Star **1,851**。
**技术栈**：Rust / DXF / CAD 命令行 / MCP / WASM。
**分类**：AI/Agent、企业AI、开发工具、新项目、重点。

**通俗说明**：ArtCraft 团队的新开源二维 CAD 编辑器，重新实现类似 AutoCAD 的绘图命令、捕捉、图层、尺寸标注、填充、图块和 DXF 文件工作流，并准备让 Agent 通过 CLI/MCP 操作。

**目标用户**：建筑平面图、室内设计、制造制图、工程咨询、CAD 软件集成团队，以及做工程 Agent 的创业者。

**核心问题**：AI 生成设计概念图容易，但真实工程图还需要精确尺寸、单位、几何捕捉、图层和可交付的 DXF；普通文生图无法保证工程约束。

**过去做法**：AutoCAD/DraftSight/QCAD 等软件人工绘图，或临时用 Python + CAD 库生成 DXF，再回 GUI 修尺寸、标注和图块。

**工作机制**：使用 CAD 命令和捕捉规则建立几何对象，保留图层、线型、标注、图块等结构；Agent 可以在受控工具接口中增删修改实体并导出 DXF。

**技术架构**：纯 Rust CAD 2D 引擎、DXF 读写、Command Registry、尺寸标注及图层系统、桌面 GUI/WASM 浏览器端和 MCP/CLI 接口。

**近期爆火/加速原因**：10月7日刚创建，10月10日 GitDiscover 记录 +596；专业创作软件 Agent-ready 的同系列新项目获得开发者关注。

**核心差异化**：强调保持尺寸、图层和工程数据结构，不是将效果图伪装成施工图；同时设计为人机和 Agent 两种控制方式。

**商业化/延伸方向**：工程图纸自动出图、户型图模板、室内设计自动制图、CAD 检查/转换和 API；可向设计院/工程公司出售私有部署与标准图集。

**中国市场机会**：国内工程制图、装修、制造行业规模大；更现实的切口是“自动生成并校验标准二维图纸”，而不是取代专业设计师。

**可借鉴场景**：从标准房型参数生成标注图；自动批量更改尺寸/图框；检查图层与标注规范；把结构化表单变为 DXF。

**风险**：官方明确 early development；复杂 DXF 兼容、中文字库、尺寸公差、专业签审和行业规范是关键风险。

**启发**：专业 AI 产品的好切口是把可核验的“专业格式输出”自动化，而非只生成看起来正确的图片。

**明确判断**：★★★★★。比纯 CAD 生图更接近交付；必须以真实图纸导入导出与误差测试验证。

### 4. [AutoHarness](https://github.com/tigerless-labs/autoharness)

**统计口径**：+596（GitHub.Locker 10/09 快照）；当前总 Star **10,956**。
**技术栈**：Python 3.11+ / Claude Code Hooks / Agent Skills / MCP。
**分类**：AI/Agent、企业AI、开发工具、基础设施、新项目、重点。

**通俗说明**：让 Claude Code 从已经完成的真实任务中自动提炼 Skill，把同场景经验合并更新，并移除长期不用的自建 Skill，减少反复手工维护 Agent 提示词与经验。

**目标用户**：重度 Coding Agent 用户、代理开发工作室、管理大量客户仓库的软件团队、Agent 平台与开发者工具厂商。

**核心问题**：Coding Agent 多次犯同一个错误、反复解释项目约束；手工写 AGENTS.md/Skills 很难跟上持续变化的工作流，还会不断产生重复规则。

**过去做法**：手工维护 Markdown/SOP，或者将整段会话塞进向量库；这些方案容易产生过时规则、上下文膨胀，缺乏去重和生命周期管理。

**工作机制**：插件监听 Claude Code 会话，有足够实际工作证据时提炼技能；对相似场景合并，对复用中的规则修订，对失去价值的自身技能淘汰，同时保留决策日志。

**技术架构**：Python 3.11+、Claude Code Plugin Hooks、项目 .claude/skills、MCP Server、技能生命周期 Ledger；项目声称零第三方 Python 依赖。

**近期爆火/加速原因**：GitHub.Locker 10月9日记录 +596/日；市场关注点从“给 Agent 一套静态 Skills”走向“技能自动维护”，且库现已超过万 Star。

**核心差异化**：自学习不是不受控制地修改所有配置：项目强调只改自己生成的技能，手工安装与已有的其他 Skill 保持不变；使用真实工作日志而非仅凭测试集打分。

**商业化/延伸方向**：企业 Agent 知识管理、团队最佳实践沉淀、行业 SOP 自动更新、技能质量审计、跨仓库 Agent 工具；长期可以按团队席位或活动会话收费。

**中国市场机会**：国内软件外包、手游运营系统维护和私有企业 Agent 都重复大量相似任务；可扩展为“每处理一张工单就自动沉淀一个可审计操作 SOP”。

**可借鉴场景**：企业后台脚本修复、同类需求复用、长期项目交接、自动整理故障/代码审查经验、客服 Agent FAQ 能力累积。

**风险**：自动总结可能把偶然成功当作普适规则；会话记录可能含密钥与客户数据；Skill 污染、过度学习和模型生成的错误规则需审批机制。

**启发**：Agent 的规模化价值不仅取决于模型有多聪明，还取决于经验能否自动变成可维护、有证据的组织资产。

**明确判断**：★★★★★+。小团队可从“安全可审计的 Skill 生命周期”切入，需重点测试真实复用收益和错误率。

### 5. [Big Arrow on the Screen](https://github.com/franzenzenhofer/big-arrow-on-the-screen)

**统计口径**：+508（GitHub.Locker 10/09 快照）；当前总 Star **580**。
**技术栈**：Swift / AppKit / macOS CLI / Codex Skill。
**分类**：AI/Agent、企业AI、开发工具、新项目、重点。

**通俗说明**：非常小的 macOS 工具：Agent 可以在屏幕上方画醒目的箭头、方框和文字，直接指出用户应该点击哪一个按钮；窗口点击穿透，提示自动消失。

**目标用户**：远程技术支持、企业 AI 助理、老人/新手电脑教学、软件客服、IT 运维和桌面 Agent 产品。

**核心问题**：Agent 能说明“请点击允许按钮”，却不知道用户现在具体看到哪个弹窗；文字指导与用户屏幕脱节，初学者尤其容易点错。

**过去做法**：发截图圈选、远程桌面、长篇文字导航、屏幕共享，以及客服口述“右上角第三个按钮”。

**工作机制**：Agent 通过 CLI 传入应用、界面元素和提示文本，Swift 原生透明窗口绘制高亮箭头；用户仍亲自点击，工具不拦截交互，无需屏幕控制权限即可绘制。

**技术架构**：Swift 原生可执行程序 + macOS AppKit/overlay window + CLI + Claude Code/Codex Skill；无后台账户和遥测。

**近期爆火/加速原因**：2026-10-08 创建，GitHub.Locker 10月9日记录 +508/日；热度来自极低实现复杂度却命中真实桌面 Agent 交互痛点。

**核心差异化**：它不替人点击高风险按钮，而是把 AI 的建议转成可见、精确、人类确认的 UI 指引；“人负责操作”使审批和安全边界更清晰。

**商业化/延伸方向**：可视化客服引导、远程软件上手助手、企业操作培训插件、RPA 人工接管界面、轻量收费桌面控件 SDK。

**中国市场机会**：企业微信客服、支付教程、软件安装支持、OA 使用培训都需要可视化一步步指引；Windows 版本可面向更广泛的国内 PC 用户。

**可借鉴场景**：会员充值操作排错时标注需要点击的入口；人工审批时高亮授权弹窗；指导客服或财务完成复杂表单。

**风险**：界面定位与版本变化可能让箭头指错；在支付、授权等敏感页面必须明确提示由用户自行判断，不能诱导错误授权；仅支持 Mac。

**启发**：Agent 和人之间的“最后一厘米交互”可能是比完全自动化更容易商业化、也更安全的机会。

**明确判断**：★★★★★。功能小但需求硬，适合快速做 Windows/浏览器扩展并验证客服节省时长。

### 6. [PPT Master](https://github.com/hugohe3/ppt-master)

**统计口径**：+372（GitDiscover 10/10 快照）；当前总 Star **59,425**。
**技术栈**：Python / PPTX 原生对象 / 文档解析 / Agent Workflow。
**分类**：AI/Agent、企业AI、增长/内容、新项目、重点。

**通俗说明**：能把主题、PDF、DOCX、网页等内容转成真正可编辑的 PowerPoint，并尽量保留原生形状、数据图表、表格、动画与演讲备注，而不是只输出一张张图片。

**目标用户**：咨询、售前、教育培训、企业管理、广告策划团队以及需要大量定制方案页的服务公司。

**核心问题**：很多 AI PPT 生成器实际上把页面渲染为图片；文本和图表难二次修改。人工做一套高质量可编辑的商业汇报又很费时。

**过去做法**：人工 PowerPoint/Keynote、Canva 模板、让 LLM 先写大纲再人工排版，或者生成图片式 PPT，后期修改成本高。

**工作机制**：解析输入资料并抽取叙事结构，再生成 PowerPoint 原生图形、标题和图表；用户可继续在 PPT 软件里修改、替换模板或补充讲述音频。
