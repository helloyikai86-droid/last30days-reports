## 1. security-audit-skill
**通俗说明**：Cloudflare 的多阶段安全审计 Skill，不只让 Agent 找漏洞，还要求记录覆盖、证据、独立复核和机器可读 findings。  
**目标用户**：安全团队、软件企业、需要高可靠 AI 审核的组织。  
**问题与旧方案**：过去靠人工审计 + SAST/DAST；直接换成单 Agent 又容易漏检和幻觉。  
**爆火原因**：最近可验证日增 +2,375，且 9/21 GitHub API 已到 18,009 Star；企业 Agent 正从“能做”转向“可验证、可追责”。  
**差异化**：执行 Agent + 独立 Reviewer + coverage ledger + schema + validator。  
**商业化/中国机会**：企业 Agent 审计控制层；可迁移到投放审核、合同、财务、客服质检。  
**风险**：不能替代专业责任主体，规则覆盖不足仍会漏检。  
**启发/判断**：高风险 Agent 应拆成执行、复核、程序校验三层。**★★★★★+**。

## 2. ECC
**通俗说明**：给 Claude Code、Codex、Cursor 等 Coding Agent 加上 skills、memory、安全和 research-first 工程方法。  
**目标用户**：高频 AI 编程团队。  
**问题与旧方案**：模型会写代码，但团队规则、记忆和质量门禁分散在文档与人工 review。  
**爆火原因**：最近可验证日增 +1,012，竞争焦点从模型能力转向 Agent harness。  
**差异化**：跨模型/IDE 的工程治理，而非单一 Coding Agent。  
**商业化/中国机会**：企业 Coding Agent 标准包、私有规则库、技能库、实施培训。  
**风险**：规则过多可能降低灵活性；模板容易被复制。  
**启发/判断**：护城河是企业 SOP 与历史反馈。**★★★★★**。

## 3. WeKnora
**通俗说明**：腾讯开源企业知识平台，把文档变成 RAG、推理 Agent 和自维护 Wiki。  
**目标用户**：企业知识管理、客服、研究、内部 IT。  
**问题与旧方案**：资料散在 PDF/文档/系统，传统搜索只能找文件；过去多靠 Elasticsearch 或自己拼 RAG。  
**爆火原因**：最近可验证日增 +858，企业 AI 价值正在从通用聊天转向内部知识执行。  
**差异化**：不仅问答，还强调推理与自维护 Wiki。  
**商业化/中国机会**：图片 PDF、企微/钉钉/飞书资料接入、行业知识助手、私有部署。  
**风险**：权限、过期知识、引用可信度和解析质量决定真实效果。  
**启发/判断**：不要卖通用 RAG，要卖行业资料接入+权限+更新+行动闭环。**★★★★★**。

## 4. mattpocock/skills
**通俗说明**：把规格、TDD、调试、代码库设计和复盘封装成 Agent Skills。  
**问题**：Agent 会写代码但常跳过澄清、测试和工程判断。  
**爆火原因**：最近可验证日增 +841；Skill 正成为 Agent 能力分发单位。  
**商业化**：行业 Skill 商店、企业私有 Skill Registry、工程 SOP 服务。  
**中国机会**：把百度投放、企微运营、财务 OA、短视频生产等 SOP 做成可执行技能。  
**风险**：复制门槛低，平台标准仍在变化。  
**判断**：做垂直 SOP 比做通用 Skill 收藏站更有价值。**★★★★☆**。

## 5. BrowserSkill
**通俗说明**：让 Agent 使用用户真实、已登录的浏览器，解决 Cookie、验证码和业务后台。  
**目标用户**：运营、企业自动化、Research Agent、Codex/Claude Code 用户。  
**旧方案**：Playwright/Puppeteer + 独立 Profile + 重登录，或等系统 API。  
**爆火原因**：最近可验证日增 +744，总量仅约 5.7k，属于较早期强加速。  
**差异化**：复用真实登录态 + 独立窗口 + Borrow Tab + 人工接管。  
**商业化/中国机会**：订单履约、客服后台、广告账户、CMS、后台录入，属于 AI RPA 2.0。  
**风险**：账号风控、误操作、平台条款、高权限安全。  
**判断**：今天最值得研究的产品机会之一。**★★★★★+**。

## 7. json-render
**通俗说明**：Vercel Labs 的 Generative UI 框架，让 AI 生成受约束 JSON，再映射成允许的 UI 组件。  
**目标用户**：AI SaaS、企业软件、动态表单/报告/工作台。  
**问题与旧方案**：聊天只返回文字；直接生成任意 React/HTML 又不稳定、不安全。  
**爆火原因**：最近可验证日增 +468；AI 产品开始从聊天框走向任务动态界面。  
**差异化**：schema + component registry，在灵活性与安全之间折中。  
**商业化/中国机会**：动态审批表、投研报告、客服工作台、运营后台、低代码 Agent UI。  
**风险**：复杂交互仍需设计；写操作权限必须严格隔离。  
**判断**：聊天框之外的重要产品形态。**★★★★★**。

## 8. OpenSpec
**通俗说明**：面向 AI Coding 的规格驱动开发，把需求、规格、实现、验收对齐。  
**问题**：AI 写代码越快，需求漂移和验收不清越危险。  
**旧方案**：PRD、Issue、技术设计文档和人工同步。  
**爆火原因**：最近可验证日增 +464；规格正在成为 AI 编码的新瓶颈。  
**商业化/中国机会**：连接禅道/TAPD/飞书需求与 GitHub/GitLab/Coding Agent，做企业研发治理。  
**风险**：规格维护有成本，小任务可能过度工程化。  
**判断**：企业价值高，但流程必须轻。**★★★★☆**。

## 9. supermemory
**通俗说明**：AI memory/context engine，把长期记忆独立成可复用基础设施。  
**问题与旧方案**：长对话和跨任务上下文会丢；过去靠向量库+自建摘要，每个应用重复做。  
**爆火原因**：最近可验证日增 +460；Agent 从单次任务走向长期协作。  
**商业化/中国机会**：企业 Agent 记忆 API、客服/销售长期上下文，连接企微、钉钉、CRM、工单。  
**风险**：隐私、删除、错误记忆、权限串数据。  
**判断**：基础设施机会明确，权限应是第一设计原则。**★★★★★**。

## 10. webcodex
**通俗说明**：让云端 ChatGPT/Claude 通过 MCP/HTTPS 操作你自己机器上的真实开发环境。  
**目标用户**：个人开发者、小团队、需要私有代码环境的企业。  
**问题与旧方案**：云端 Agent 难直接访问本地仓库/命令/测试；过去靠本地 Agent、远程桌面、上传代码或自建 SSH Runner。  
**爆火原因**：最近可验证日增 +202，总 Star 仅约 1.4k，是今天最值得关注的早期信号之一。  
**差异化**：把现有开发机变成云端 Agent 可调用的 Runner，而不是再造聊天客户端。  
**商业化/中国机会**：团队 Runner 托管、私有开发 Agent 网关、权限审计、内网连接。  
**风险**：远程命令执行权限极高，必须做最小权限、隔离、审计和密钥管理。  
**判断**：早期但值得重点跟踪。**★★★★★**。

## 今日最值得研究的 3 个机会

1. **BrowserSkill：真实登录态 Agent → AI RPA 2.0**。最容易落到订单、客服、广告后台、CMS 等真实业务流程；中国大量 SaaS/API 不完整，使这一方向尤其有价值。
2. **json-render：Generative UI → AI 动态软件界面**。模型不再只输出文字，而是按任务即时生成受控表单、报告和操作面板，适合企业软件和垂直 SaaS。
3. **security-audit-skill + OpenSpec：Agent 可靠性/研发治理层**。代码生成越来越便宜后，规格、证据、复核、验收和审计会成为企业真正愿意付费的部分。
