## 1. [REA](https://github.com/morluto/rea)

**热度**：+7,738（GitHub Trending stars today，滚动窗口）；**总Star**：26,342；**技术栈**：TypeScript / MCP / Ghidra / Hopper / Electron / V8

**通俗说明：**连接网页行为、Electron/JS 与原生二进制的逆向调查 Agent：它不仅解释代码，更沿着工具证据链追溯软件实现。

**目标用户：**经许可的软件迁移团队、兼容性工程师、安全研究者、工业软件团队和技术尽调人员。

**核心问题：**一个功能横跨前端、JS runtime、进程通信与原生模块；工程师难以快速定位闭源系统的真实行为。

**过去做法：**原本使用 DevTools、抓包、Ghidra、Hopper、调试器轮流查证，并手工整理证据与文档。

**项目定位：**Reverse Engineer Anything，目标是把复杂软件调查转成可编排、可复核的专业 Agent 工作流。

**机制：**先观察应用行为，再跟踪脚本与二进制线索，利用专业工具找函数、引用及调用关系；重要推断必须关联证据。

**技术架构：**TypeScript 调度、MCP 工具接口、V8/Electron 分析、Ghidra/Hopper 适配；使用范围取决于目标授权。

**近期热度原因：**本期+7,738，较前期+2,963滚动快照显著加速；跨专业工具的调查自动化受到集中关注。

**核心差异化：**相较只有少量 Ghidra 只读接口的聊天插件，REA 跨越应用行为、脚本执行、原生层并强调证据链。

**商业化与延伸：**做授权系统迁移顾问、兼容性评估工具、固件文档化、企业内网逆向研究台；按项目/席位交付。

**中国机会：**国内工业软件替代、IoT 固件升级、遗留客户端兼容有真实需求，前提是取得明确的软件分析授权。

**可借鉴场景：**为旧客户端建立功能证据图；评估代码迁移风险；生成可回溯的技术调查报告。

**风险：**逆向属于双重用途，涉及版权、商业秘密、EULA、DRM、密钥与授权边界，企业必须做审计。

**启发：**专业 Agent 越来越像一名能操作全套专业软件并解释证据的研究人员。

**明确判断：**★★★★★+；今日加速最强，但只建议合法授权的专业商业场景。


## 2. [AnyPS5](https://github.com/boykopovar/AnyPS5)

**热度**：+4,669（GitHub Trending stars today，滚动窗口）；**总Star**：15,739；**技术栈**：C++ / Executable Relinking / SPIR-V / Shader Recompiler

**通俗说明：**尝试将主机可执行内容重链接为 Windows/Linux 原生程序的实验性工具，而非普通完整模拟器。

**目标用户：**游戏兼容性研究者、图形程序员、游戏保存团队与有授权的移植工作室。

**核心问题：**主机程序依赖专有可执行格式、系统 PRX 和 Shader/图形调用，PC 无法直接执行。

**过去做法：**完整模拟器需要重现大量系统行为；逐游戏人工移植非常耗费工程时间。

**项目定位：**以自动 executable porting 为方向的兼容性实验，不应理解为成熟通用的 PS5 游戏运行器。

**机制：**Relinker 转换可执行结构，系统兼容层承接接口，再将 Shader 转为 SPIR-V，尝试目标机器原生运行。

**技术架构：**C++ 重链接工具、系统库兼容实现、Shader 翻译与 Windows/Linux 可执行构建实验。

**近期热度原因：**今天+4,669，早前约+2,725，技术圈二次传播；“不是模拟器”成为最强传播点。

**核心差异化：**通过提前移植转换而非持续模拟完整主机，探索另一种跨平台性能与兼容路线。

**商业化与延伸：**授权游戏迁移工具、兼容性研究、Shader 分析、开发者技术教育；短期不适合承诺通用收费服务。

**中国机会：**国内 PC/主机技术社区、游戏工作室可研究自动重链接路线，正规产品须有权利方授权。

**可借鉴场景：**研究移植可行性、老游戏保存、Shader 翻译与开发者教程。

**风险：**当前兼容范围有限；版权、EULA、DRM、反作弊和平台认证限制很大。

**启发：**程序跨平台适配不只有完整模拟器，还可拆成重链接、兼容层与图形转换。

**明确判断：**★★★★☆+；技术热度极高，但商业实现与法律约束明显。

## 8. [Cayu](https://github.com/cayu-dev/cayu)

**热度**：+516（GitHub.Locker 2026-10-07日增快照；非今日日增）；**总Star**：约704（10月7日快照）；**技术栈**：Python3.11+ / Durable Sessions / ToolPolicy / FastAPI

**通俗说明：**专为长期运行、会调用真实业务接口的 Agent 设计的 Runtime，解决断点恢复、审批、幂等、预算、审计与不确定的外部副作用。

**目标用户：**企业 Agent 产品开发者、自动订单履约、客服运营、财务 OA 和跨后台 RPA 团队。

**核心问题：**模型调用后可能出现崩溃、超时、重复发券、权限错用或中途待人审批，单次脚本很难保证业务正确。

**过去做法：**通常用 LLM SDK 加 Celery/数据库/自写重试代码拼装，出现异常后无法确认外部操作到底执行了没有。

**项目定位：**Cayu 把持久会话、工具权限、人工审批、状态恢复、成本与评测做成可组合框架原语。

**机制：**Tool Effect 声明潜在副作用，状态以事件保存；允许暂停/恢复和人工审批，结果不确定时先对账再重试。

**技术架构：**Python、durable session/event store、Policy/Approval、worker/runner、FastAPI 控制面与 Evals。

**近期热度原因：**10月7日快照+516，低基数增长明显，反映用户开始重视生产 Agent 的错误恢复。

**核心差异化：**不只实现 Agent 调工具，更把权限、幂等、费用、轨迹验证纳入执行生命周期。

**商业化与延伸：**企业 AI 执行基础设施、业务审批插件、合规履约 Agent、任务运营与审计 SaaS。

**中国机会：**特别适合游戏累充福利、卡密核销、订单查询、企微客服、钉钉 OA 这类“错发一次就损失钱”的业务。

**可借鉴场景：**订单收款确认→准备发货→人工批准→幂等核销→失败自动对账的沙箱演练。

**风险：**学习与集成成本较高；ToolPolicy 不等于天然代码沙箱，真实凭据必须隔离。

**启发：**企业 Agent 的产品护城河正在从 Prompt 质量转向可恢复的可信执行。

**明确判断：**★★★★★+；优先做企业场景最小 POC，价值大于只看模型能力。

**目标用户：**企业业务负责人、AI 员工团队、岗位 SOP 产品商、企业内工具连接器实施商。

**过去做法：**过去拷贝 System Prompt、散落的岗位手册，再单独配置 CRM、工单与数据平台接口。

**项目定位：**11类角色/管理插件样本，把岗位 Skills、Slash Commands、MCP Connectors 与子 Agent 打包。

**机制：**使用 manifest 声明插件，连接器提供数据与动作，Skills 编码步骤和质量标准，Commands 触发显式任务。

**技术架构：**Markdown+JSON 声明，plugin.json、.mcp.json、commands/、skills/；面向 Claude Cowork 也兼容 Claude Code。

**近期热度原因：**本轮 GitHub Trending +392，代表官方把 Agent 的使用单位从模型能力推向岗位和企业流程。

**核心差异化：**不仅告诉 AI 做什么，还指定从哪里拿数据、可以执行哪些操作、输出什么交付物。

**商业化与延伸：**行业插件开发、企业定制、连接器部署、岗位测试评估与维护订阅。

**中国机会：**可做游戏运营、私域客服、电商投放、财务 OA 的中文版，并适配企微、飞书、钉钉。

**可借鉴场景：**标准客服工单总结、销售预研、营销内容报告、账务对账资料、知识库回填。

**风险：**读取企业数据和发出外部动作仍需权限、审批和审计；纯 Prompt/Markdown 易复制，行业集成才有壁垒。

**启发：**AI 员工市场的商品将是“岗位工作流+系统连接+评测”，而不仅是 Prompt。

**明确判断：**★★★★★；适合小团队做垂直行业服务。

**可借鉴场景：**超大项目调试、PDB/符号诊断、比较构建耗时、工具链研究。

**风险：**Windows x64 优先且仍 Alpha；官方特定场景的提速自测不能当普遍保证。
