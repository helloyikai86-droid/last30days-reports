## fast-anything｜只用Rust重写性能热点

GitHub：[https://github.com/EL4CTEO/fast-anything](https://github.com/EL4CTEO/fast-anything)

**增长与去重：**首次入库；美西11月22日部分自然日新增 **1,510 Star**（仅16小时20分钟，非严格滚动24小时），采样时总Star **1,875**；前窗速度对照：6.1倍。

### 1. 简单理解
给Python、Node、Ruby等程序做性能采样，只挑最慢且容易迁移的少量函数交给Coding Agent用Rust重写，经过行为回放验证才启用；不是整站重写。

### 2. 目标用户
运行脚本批处理、SaaS后台、数据分析、爬虫和内容生产任务的技术负责人；已有Python/Node网站和工具的小团队。

### 3. 核心问题与传统解决方式
应用变慢时常凭感觉优化，甚至计划把整个应用换语言，导致周期长、风险高、性能收益不确定。
**旧做法：**手动profile、逐函数重构、全项目Rust改写或升级机器；验证一般靠少量单元测试，忽略真实输入边界。

### 4. 产品定义与工作机制
一个将“发现热点→采样真实调用→Agent迁移→结果校验→A/B跑分→随时回滚”打包为命令行和MCP工具的性能优化工作台。
**执行逻辑：**scan按耗时与可迁移性排序；port记录最多500次真实输入输出并创建单函数Rust crate；verify重放原行为和衍生边界样例；enable/disable替换或回退；bench交错测试整条业务链。

### 5. 技术栈与架构
Rust / PyO3 / napi-rs / FFI / MCP / Agent Skills。
Rust核心与CLI，Python通过PyO3、Node通过napi-rs，其他语言经C ABI与JSON桥连接；适配Claude Code/Codex等Agent，带MCP工具与可撤销注入。

### 6. 为什么最近热门

### 7. 与常见方案的差异
不是把全部代码迁往Rust，而是把可测量的热点函数按可回滚粒度迁移；“行为相符且确实更快”是上线门槛。

### 8. 商业化及延伸方向

### 9. 中国市场机会
在游戏素材处理、订单报表、会员库存核算、内容去重、字幕转换等高频任务中先找CPU热点；中文软件外包公司可打包成性能优化验收服务。

### 2. 目标用户

### 3. 核心问题与传统解决方式

**执行逻辑：**将不同页面视觉token组织成可延续的解析序列，通过SR-SWA限制对历史内容的关注规模；支持多页推理和推荐的SGLang服务流程。

### 5. 技术栈与架构
Python / PyTorch / Transformers / SGLang / SR-SWA。

### 6. 为什么最近热门
