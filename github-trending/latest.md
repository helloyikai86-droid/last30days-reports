### 1. Scout｜★★★★★
**GitHub：** https://github.com/outcrawlai/scout
**增长：** +721（10月14日第三方日榜快照）；**总 Star：** 831；**技术栈：** TypeScript / Node.js 22+ / CDP / Playwright / LLM。
**数据源：** https://github.locker/topics/ai-agent（2026-10-14）；GitHub Trending滚动 stars today 代理（非严格北京时间连续24小时增量）。
**通俗说明：**能使用真实浏览器完成多步骤网页任务的开源 Agent：读页面、点击、输入、翻页并返回结构化结果，不只是抓取一页 HTML。
**目标用户：**运营人员、QA 自动化工程师、企业信息采集团队、需要操作网页后台的独立开发者。
**核心问题：**业务后台往往没有完整 API，动态页面操作需要人工；纯爬虫又难以处理交互、分页和上下文变化。
**过去做法：**人工操作浏览器；为每个网站写 Playwright/Selenium 脚本；RPA 依赖固定坐标或 DOM 定位，改版后频繁失效。
**产品定位：**基于 Outcrawl 的 Scout 浏览器 Agent；既可在其云浏览器运行，也支持在本机连接 Chromium/CDP。
**工作机制：**先由模型理解任务和页面状态，再驱动浏览器执行动作；支持多角色模型职责拆分、运行回放、失败时返回已获得的信息。
**技术架构：**TypeScript/Node.js + 浏览器控制接口 + 可替换 Chat Completions 模型 + 云端或本地浏览器；官方示例可以输出结果与 replayUrl。
**近期热度原因：**GitHub.Locker 在10月14日记录约+721日增，仓库10月13日创建，属于近期新仓库迅速获得关注；具体传播渠道未获独立证实。
**核心差异化：**把真实浏览器运行、自然语言任务、结构化输出和可观看回放组合为可交付流程；与单纯网页摘要或单站点爬虫不同。
**商业化与延伸方向：**可作为自动化服务底座，为特定行业销售数据采集、人工审批的后台流程自动化、浏览器回归测试和操作留痕服务。
**中国市场机会：**针对订单查询、游戏运营管理后台、商品竞品信息和企业内部网页系统做垂直适配，按工作流/坐席/运行量收费。
**可借鉴场景及验证实验：**先用3个获授权的后台测试：跨页查询用户记录、导出日统计、核对订单金额；统计成功率、重试率、人工接管和单次成本。
**风险与适用边界：**网页登录、验证码和反爬机制不能成为绕过服务条款的理由；生产流程必须最小权限、人工确认、访问审计与幂等防重。项目称云端支持住宅网络及验证码处理，需审查合规性。
**启发：**真实业务自动化的产品壁垒在场景适配、故障恢复、权限边界与可解释证据，不在“浏览器会点击”。
**明确判断：**★★★★★｜值得优先做受控 PoC；能快速测量真实人力节约，但不应直接让它无审批执行付款、退款或发货。
**核验依据：**GitHub 官方 README 核实多模型、浏览器与回放；日增来自 GitHub.Locker 2026-10-14 榜单，非本次独立24h差。

### 2. XERJ｜★★★★★

**核心问题：**Agent 经常反复读取整份文件、日志和历史会话，造成 Token 浪费，甚至漏掉关键代码证据。
**过去做法：**grep/rg + 人工定位、向量数据库自行搭建、聊天摘要或者每次重新浏览代码库。

**工作机制：**启动后自动索引目录，使用关键词与可选语义检索返回相关段落和文件行号；能通过 MCP 接入 Agent。

**商业化与延伸方向：**企业研发搜索服务、Agent 记忆层、内部文档知识库、运维日志分析和可控私有部署。
**中国市场机会：**制造业技术文档、手游客户端代码、营销后台脚本、企业知识库都可使用，不必一开始就建立重型 RAG 平台。
**可借鉴场景及验证实验：**取一组真实 Codex 开发任务，比较启用前后的Token、正确率、时间和人工修正次数，避免只测压缩比例。
**风险与适用边界：**README 提到的2.7倍Token优化是项目自身案例，不能推广为普遍事实；`--insecure` 会关闭TLS和API鉴权，严禁直接暴露公网。
**启发：**AI 成本优化应以“完成同样正确任务的总成本”为指标，检索少花 Token 若带来错误反而得不偿失。
**明确判断：**★★★★★｜功能聚焦、可量化，但需严格验证安全边界、长仓库增量索引性能和结果召回率。
**核验依据：**GitHub 官方 README 确认自动索引、MCP、检索及不安全模式告警；日增为GitHub Trending滚动快照。
